# Bookmarkd — Architecture

## 1. Shape

```
Flutter app ──supabase_flutter──▶ Supabase (Postgres + RLS, Auth, Storage)
     │
     └──dio──▶ Google Books API (primary catalog)
          └──▶ Open Library Search API (fallback on failure / rate limit)
```

No custom backend. All multi-row invariants live in Postgres (constraints,
triggers, `security definer` RPCs). The mobile app only ever holds the anon key.

### Layers (per feature, only those it needs)

| Layer | Contents | Rules |
|---|---|---|
| `domain/` | Immutable models, value objects, repository interfaces, pure functions | No Flutter, no Supabase imports |
| `data/` | Supabase / HTTP implementations of repositories, JSON mapping | Parses outside data once, throws `AppFailure` |
| `presentation/` | Cubits, pages, widgets | Talks to repository interfaces only |

### Configuration

`AppConfig` reads `--dart-define`s (`--dart-define-from-file=.env`). `SUPABASE_URL` and
`SUPABASE_PUBLISHABLE_KEY` are required; startup fails with a clear error without them.

Dependency injection: `get_it`, configured once in `app/di.dart` after `Supabase.initialize`.

## 2. Glossary

| Term | Meaning |
|---|---|
| **Work** (`books`) | The literary work: title, authors, description, categories. One row per work. |
| **Edition** (`book_editions`) | A specific printing: ISBNs, publisher, date, pages, cover, language, external ids. Many per work. |
| **Library entry** (`user_books`) | One user's relationship with one **work**: status, progress, rating, favorite, dates. It points at the edition they read. |
| **Reading status** | `want_to_read`, `reading`, `finished`, `dnf`. |
| **Rating** | Half-star value 0.5–5.0, stored as integer half-stars 1–10. Lives on the library entry. |
| **Review** | Text written by a user about a work. At most one per user per work. |
| **Reading session** | One progress update: page/percent reached on a date. Progress history = sessions. |
| **Activity** | Feed event generated by the database (`started`, `finished`, `rated`, `reviewed`, `dnf`, `want_to_read`). |
| **Reading history** | Finished entries. Finished status and goal participation are separate: only a dated read (`finished_at`) belongs to a year and counts toward that year's goal. A book **read some time ago** is finished with `finished_at` null: it counts in totals, never in a year. Undated and earlier-year finishes post no feed activity. |
| **Finish Sheet** | The single screen every path to Finished goes through. From Reading it defaults to counting toward this year; otherwise the reader chooses "Count in my year" (with a date) or "Read some time ago". |
| **Notification** | A notice for one user, written by a trigger. MVP: `follow` ("X started following you"), removed again on unfollow. |
| **Catalog book** | A normalized search result from an external API, not yet stored. Identified by external id key (`gb:<id>`, `ol:<key>`). |

### Library model decision

A user has **at most one library entry per work** (`unique(user_id, book_id)`).
The entry records which edition they own/read (`edition_id`). Re-adding a
different edition of the same work updates the existing entry instead of
creating a duplicate shelf item.

### Deduplication

When a catalog book is saved (`upsert_catalog_book` RPC):
1. Edition matched by `google_books_id`, then `open_library_id`, then `isbn_13`, then `isbn_10`.
2. If found, its work is reused. ISBNs are **not** unique constraints (Google
   sometimes returns several volumes sharing an ISBN), only lookup keys.
3. Otherwise a work is matched by normalized `(lower(title), lower(first author))`,
   else created, and the edition is attached to it.

Only metadata for books someone added is stored — never the catalog.

## 3. Database

```
auth.users 1─1 profiles
profiles 1─* user_books *─1 books 1─* book_editions
user_books *─1 book_editions
user_books 1─* reading_sessions
profiles 1─* reviews *─1 books           unique(user_id, book_id)
profiles *─* profiles via follows        pk(follower_id, followee_id), check follower <> followee
profiles 1─* activities *─1 books
activities 1─* activity_likes            pk(activity_id, user_id)
profiles 1─* notifications            unique(user_id, actor_id, type); read_at set by the recipient only
```

Privacy: `profiles.is_private`. A private user's library, reviews and
activities are visible only to themselves (no follow-request flow in MVP).
Email stays in `auth.users`; `profiles` holds no sensitive fields.

Server-side functions (all `security invoker` unless noted):

| Function | Why it is a function |
|---|---|
| `upsert_catalog_book(jsonb)` *definer, service role only* | Called by the `save-book` Edge Function with server-fetched metadata; dedup is atomic. |
| `log_reading_progress(...)` | Validates page against edition page count, updates entry + inserts session in one transaction. |
| `get_feed(cursor_ts, cursor_id, page_size)` | Keyset-paginated, joined feed with like counts. |
| `get_book_stats(book_id)` | Community average rating, rating count, reader count. |
| `get_popular_books(limit, category)` / `get_trending_books(days, limit)` | Counts from real library data only. |
| triggers on `user_books`, `reviews` | Emit activities so the feed cannot drift from the data. |
| trigger on `follows` *definer* | Writes / removes the followee's follow notification; clients cannot insert notifications. |

## 4. Routes (`go_router`)

```
/welcome  /login  /register  /forgot-password      (signed out)
/onboarding                                          (signed in, not onboarded)
StatefulShellRoute (bottom bar):
  /home  /search  /library  /activity  /profile
/book/:bookKey               bookKey = internal uuid | gb:<id> | ol:<key>
/book/:bookKey/progress      reading progress & history
/book/:bookKey/review        write / edit review
/users/:userId               another reader's profile
/users/:userId/followers     /users/:userId/following
/authors/:name               one author's catalog books, searchable by title
/notifications               follow notices (bell on Home)
/profile/edit
```

The redirect is a pure function of `SessionState` (unknown → splash,
signed-out → `/welcome`, needs onboarding → `/onboarding`).

## 5. External APIs

| API | Use | Notes |
|---|---|---|
| Google Books `GET /books/v1/volumes?q=` | Search (`intitle:`, `inauthor:`, `isbn:`), volume detail | Optional `GOOGLE_BOOKS_API_KEY`; 429/5xx/timeout → fallback |
| Open Library `GET /search.json` | Fallback search | Sends identifying `User-Agent`, limited `fields` |
| Open Library Covers `covers.openlibrary.org/b/id/<id>-L.jpg` | Fallback covers | |

## 6. Design system

Tokens in `lib/app/theme/`: colors (below), spacing on an 4/8pt scale,
radii 6/12/16, NotoSans (bundled in assets/fonts) type scale. Shadows: none except the bottom sheet.

| Token | Hex |
|---|---|
| background | `#F7F7F2` |
| surface | `#FFFFFF` |
| textPrimary | `#202820` |
| textSecondary | `#7B827B` |
| accent | `#365B48` |
| accentSoft | `#E3EDE4` |
| border | `#E7E9E3` |

Covers use a 2:3 aspect ratio everywhere; a missing cover renders a typeset
placeholder (title + author on a tinted card) instead of a broken image.

## 7. Recommendation heuristic (MVP)

"Popular in *<your most-read genre>*": the most-added books in the community
whose category matches the most common category in your library, excluding
books you already have. Labelled as such in the UI. No AI, no personalization
claims.
